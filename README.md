# Prospective Wine author run with raw strace

This is a public candidate for a GitHub-hosted Ubuntu experiment. It downloads and verifies the exact public author-code archive and UCI Wine input, builds a Docker image, and runs the unchanged author learning/pruning code through a compatibility caller for 25 fixed splits. The container has no network, a read-only root filesystem, dropped capabilities, and only the result and trace paths writable. Raw `strace` captures selected file, read, process-start, and connection syscalls.

The first job retains success or failure receipts, including exact copies of the downloaded author ZIP and Wine raw data. A second VM verifies the source snapshot, the expected GitHub repository/commit/run identity supplied by that VM, the retained input bytes against frozen lengths and SHA-256 values, the returned 25-row CSV and arithmetic, and positive `openat`/`read` events for the Wine file before asking GitHub to attest the receipt tar. An offline caller must obtain those expected identity values from an independently trusted source, such as the GitHub run and artifact attestation; passing values copied from the tar would not establish identity. The repository does not include the author archive, UCI data, API keys, human labels, or historical execution evidence; a future run artifact would include the two public input files.

The target is Leboeuf et al., NeurIPS 2020, Table 1 Wine/Ours, reported as `0.904 ± 0.046`. The Wine data were used to choose the prior exponent in the paper, so this is not an independent blind test of that number. A successful workflow would add a **new prospective execution observation** tied to a GitHub workflow identity. It would not prove a complete byte-level readset, authenticate the original 2020 run, establish scientific ground truth, or show an advantage over a same-information fixed baseline.

The retained dataset is [Aeberhard and Forina, *Wine* (1992), UCI Machine Learning Repository, DOI:10.24432/C5PC7J](https://archive.ics.uci.edu/dataset/109/wine), licensed there under CC BY 4.0. The author ZIP includes its own MIT license file.

The workflow is manual (`workflow_dispatch`). [The first hosted run](https://github.com/SHiJiE1115/newproj/actions/runs/36583899749) **failed**: the author code produced a 25-row CSV and selected syscall trace, then tried to write its summary to read-only `/probe/out` instead of the writable `/out` mount. The second job was skipped; this is not a passing or attested experiment. Revision v02 fixed that path but was not run. Revision v03 additionally checks the receipt's GitHub identity against values supplied by the second VM; it also has **not run**. This v04 candidate retains the downloaded input bytes for second-VM verification; it has **not run**. The runner's source-byte freeze is in `experiment/FREEZE.json`; the GitHub workflow will fail closed if a frozen file changes. The verified author ZIP and UCI data are fetched at run time from the pinned URLs in `experiment/PROTOCOL.json`. Ubuntu base-image digest is pinned; apt package versions are observed and recorded during the build/run, not byte-pinned in this candidate.

If a further run is authorized after this candidate is reviewed and published, the workflow remains **Actions → RRNC prospective Wine author strace → Run workflow**. The job is capped at 25 minutes; the container author step at 300 seconds. Download and preserve the artifact and attestation because Actions artifacts expire. A failure is retained as a failed protocol run and must not be called a successful trace. The original P1 release gate and local reserve set are unchanged.
